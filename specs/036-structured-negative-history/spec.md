# Historical structured findings

## Goal

A repeated request on the same head cannot erase validated typed code or security findings. Formal approval alone leaves the gate pending until a strictly newer authoritative structured completion explicitly clears the affected review channel. Malformed or foreign-head historical state does not gain a permanent veto. Native findings and unresolved threads retain their existing veto.

## Acceptance Criteria

- Old validated current-head security findings remain pending after a repeated request and formal approval.
- A strictly newer clean structured completion explicitly clears the affected channel.
- Historical malformed/foreign-head state does not permanently veto current proof.

- Negative presentation recognizes raw HTML blocks after code without allowing them to interrupt a paragraph.
- Only an explicitly finding-bearing typed companion may isolate its warning trigger from the other channel’s completion clock; contradictory clean companions remain observation-time invalidators.
